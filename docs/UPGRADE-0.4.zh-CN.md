# v0.4：连续滑动、拼音补全与更长语音

## 本版

- 顶部切换栏和底部控制固定。键盘主体使用原生横向分页滚动，跟随手指移动，两页可同时可见；松手吸附，左右循环。点顶部选项也走滑动动画；系统“减弱动态效果”开启时直接切换。
- 拼音完整匹配优先；没有完整匹配时先补全当前输入，再考虑较短的拼音前缀。例如 wo → 我、wom / wome → 我们。候选消费已输入的全部字母，不留下 m。仍是基础词库补全，不包含完整系统输入法的整句预测、用户词频学习或任意混合简拼。
- 主 App 会话可选 10、30、60 分钟，默认保留 10 分钟。会话期间持续使用麦克风，录音指示持续显示；闲置声音丢弃。通话、设备变化、网络中断与系统终止仍可能结束会话。
- 单次录音从 60 秒扩展到 5 分钟。电脑桥接按桌面麦克风的 60 秒片段、4 秒重叠方式提交，不把整段长音频塞进一次模型推理。
- iPhone 和电脑桥接需要一起更新。旧桥接仍只支持 60 秒，新主 App 会提示更新。

## 为什么还需要开启主 App 会话

60 秒、10 分钟是早期实验版的产品设置，不是 iOS 强制的统一上限。会话可以延长，但键盘扩展无法直接使用麦克风；录音由包含它的主 App 负责。不能承诺取消首次开启或在系统终止后自动恢复录音。后续可研究快捷指令、控制中心入口等用户主动的启动方式，需分别验证 iOS 版本与免费签名支持。

Typeless 的公开通用帮助页写单次听写上限 9 分钟，但没有单独注明 iPhone 是否相同。它的 iOS 帮助也说明需要通过主 App 访问麦克风时会发生 App 切换。

## AWS 后续路线（本版不部署云端）

可把识别服务和热词处理搬到 AWS：手机录音 → HTTPS 认证入口 → 私有 ASR 工作进程 → 共享版本的热词与纠正规则 → 手机键盘。这样个人电脑可关闭，手机通过 Wi-Fi 或蜂窝网络使用。

当前代码仍限制私人局域网 HTTP，不能直接把 AWS 公网地址填进去。云版需要 HTTPS 客户端、服务器认证与证书、用户隔离、请求大小与并发限制、超时取消，以及热词的私人同步/版本管理。公网服务不应直接暴露当前没有客户端认证的桌面 6016 端口。

模型权重、推理引擎、数字处理和热词算法需锁定同一版本；先在 Linux 容器验证现有 ONNX/GGUF 模型和对应推理后端，再根据实测速度选择 CPU 或 GPU 实例。Windows 打包程序不能直接作为 Linux 服务运行。为兼顾手机和电脑，应让两端访问同一个受认证服务或同步同一个带版本的私人词库；上传个人热词属于之后单独授权的云端数据操作，本版未上传。

AWS 服务运行、磁盘和网络会产生使用费用。Apple 零年费侧载与 AWS 运行费用是两件事；不能保证云服务器永久免费。后续部署前应确定地区、使用频率、延迟目标和预算，先给出可复查的费用估算，不在本版创建收费资源。

手机独立离线是另一条路线：把模型也放到 iPhone 主 App 中运行。可能减少服务器依赖，但需另测模型大小、内存、耗电和识别质量，不能默认等同当前电脑大模型。即便使用 AWS，iOS 麦克风与免费签名续期规则也仍然存在。
